Async Error Handler

Eliminate repetitive try/catch boilerplate across your controllers and prevent unhandled promise rejections from hanging your Node.js server.

1. The Problem

In standard Express.js route handlers, an uncaught exception inside an async function will not be handled by Express by default. The client request will hang indefinitely until timeout, and Node.js will log an unhandled promise rejection.

Wrapping every single controller with try { ... } catch (err) { ... } creates noisy, bloated code.

2. The Solution: asyncHandler

Located in src/core/asyncHandler.js, this utility safely forwards any rejected promises straight to the next Express error middleware: 

import { Router } from 'express';
import { asyncHandler } from '../core/asyncHandler.js';
import { responseApi } from '../libs/RestApiHandler.js';

const router = Router();

// Wrap any async function:
router.get('/products', asyncHandler(async (req, res) => {
    // If this throws (e.g. database disconnect), it's caught automatically:
    const data = await fetchDatabaseRecords();
    return responseApi(res, data, null, "Fetched successfully");
}));

3. Global Error Handler Middleware

TeapotApps provides a centralized error middleware in src/app.js that intercepts all uncaught errors and transforms them into a structured JSON envelope: 

// In src/app.js
app.use((err, req, res, next) => {
    console.error("Unhandled Error:", err);
    if (res.headersSent) {
        return next(err);
    }
    const statusCode = err.status || err.statusCode || 500;
    return res.status(statusCode).json({
        data: null,
        meta: null,
        status: {
            code: statusCode,
            message_client: err.message || "Internal server error"
        }
    });
});

4. Response Output

When an unhandled exception occurs, the client receives a predictable 500 status:

{
  "data": null,
  "meta": null,
  "status": {
    "code": 500,
    "message_client": "Connection to database timed out"
  }
}
Best Practice: Use asyncHandler on external API calls, database operations, or file I/O to ensure graceful degradation without crashing the Node process.
